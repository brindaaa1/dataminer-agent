# 明细表汇总特征能带来多少提升（Home Credit）

检验集 24000 人，其中坏客户 1986 人；同一切分、默认 LightGBM。

| 特征 | 检验集 AUC |
|---|---|
| 只用主表 | 0.7464 |
| 主表 + 汇总特征 | 0.7596 |

- 差值 +0.0131，90% 区间（下界即单侧 95% 下界）[+0.0090, +0.0178]
- 这份检验集能分辨的最小提升约 0.0086
- 参照：现有 agent 在 Home Credit 上用特征模板得到的最终检验 AUC 是 0.769（examples/baselines_home_credit.json，切分不同，只作量级参考）
## 结论

**提升是真的**：只加了两张明细表（征信、历史申请）的 5 种简单汇总，AUC 就从 0.746 升到 0.760，提升 0.013，超过这份检验集能分辨的最小提升（0.0086），单侧 95% 下界大于 0。对比一下，README 里说单表上加派生特征、微调参数的提升「往往只有千分之几」，这次是它的好几倍。

**还有空间**：这次没用还款流水、信用卡、分期这三张表，也没有按时间窗口汇总（比如近 90 天）。现有 agent 用特征模板（含时间窗口）在另一种切分下得到 0.769，说明再往下做还能更高。

**决定**：多轮改进里「明细表汇总特征」这一类值得投入。它也正好是需要人来定口径的地方：用哪些表、多长的时间窗口、截止时间怎么定。
